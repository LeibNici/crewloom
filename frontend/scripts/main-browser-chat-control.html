2. 角色切换与角色世代

候选角色来自 auth:check.data.roles（两种合成角色）。在产品右上角账号菜单里切换角色， 客户端会带 X-Role 重新请求 roles:check；本机按请求角色回显，并推进角色世代。 切换角色不清令牌（不需要重新登录），这是与"会话失效"的关键区别。

3. 失效注入（during-stream / during-tool）

真实分支（源码固定）：
① 401 + ROLE_NOT_FOUND_FOR_USER → 角色失效：保留登录、清角色选择、重读 auth:check+roles:check，不跳登录页；
② 其它 401（如 EXPIRED_TOKEN）→ 会话失效：清会话并回到 /login。
只有走产品请求管线的动作会广播全局副作用；原生工具卡是 SDK 直连，401 只显示卡片文案。 因此"运行中工具失效"请用 /tasks/ai（AI 任务页的"提交决定 / 继续执行"走产品管线）。

5. 会话流与缓存（drop / 停止 / 续流）

Main 可直接操作的步骤
  1. 会话输入区发送 [[drop]]：外置连接被真实切断（服务端 res.destroy，不是干净的 stream_end）。预期：已收到的文字保留，并出现中文断线说明；不会一直停在“正在生成”。
  2. 发送 [[slow]]，看到“第 1 段…”后立刻点“停止”：预期是正常终态（不是普通失败提示），且历史里只有已经生成的分段。
  3. 再发送 [[slow]]，生成中离开并重新打开该会话（或刷新页面后重新进入）：预期走 cacheReplay，从缓存位置续上剩余分段。
  4. 发送 [[nocache]]，生成中重开该会话：真实语义是「服务端仍在后台工作」（收到 chunks_cache_missing，界面显示“在后台工作中/点击刷新”），不是假错误。等控制页该会话从 streaming 变 idle（后台生成已落库）后，点界面的“刷新”即可读到完整内容，loading 自然结束。
  5. 流进行中在右上角账号菜单切换角色：不需要重新登录；roles:check 按新角色重读并推进角色世代。工具决定/续跑的角色失效（401 ROLE_NOT_FOUND_FOR_USER）与会话失效（401 EXPIRED_TOKEN）用第 3 区分开注入。
